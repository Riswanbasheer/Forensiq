Evaluation on labelled scenarios

Each scenario has a known answer. A score of 25 or more counts as “incident detected”.

How the model applies security risk management

StageIn ForensIQ
Identify assetsAsset criticality sets the impact value for every investigation.
Assess riskLikelihood from the detection score, times impact, gives a rating from 1 to 25.
Treat riskEach triggered indicator maps to a recommended control and an ATT&CK technique.
Monitor and reviewThe dashboard tracks incidents, severity and the most frequent techniques.
Evidence integritySHA-256 hashing and a hash-chained custody log make tampering detectable.

Self-audit: known limitations

IDRatingLimitationPlanned fix
A-01MediumRules plus two simple behavioural checks, with no trained model; novel attacks can be missed.Train an anomaly model (for example an isolation forest) on baseline logs.
A-02MediumReads text logs (ISO-timestamp and Linux syslog formats), not EVTX, pcap or disk images.Add parsers such as Plaso, Volatility and Zeek.
A-03MediumCustody log lives in the browser; it is not signed or write-once.Use an append-only store, digital signatures and trusted timestamps.
A-04MediumOnly seven scripted scenarios, so accuracy figures are indicative.Evaluate on a labelled public dataset and report precision and recall.
A-05LowThreat-intelligence list is static.Consume live STIX/TAXII feeds.
A-06LowIndicator weights are expert-set, not calibrated.Calibrate weights against labelled incidents.
A-07HighThe login is a browser-only demo: accounts and page code sit on the user’s device, so it cannot protect data from that user.Move authentication to a server with hashed passwords, sessions, rate limiting and MFA.
A-08MediumAdmin controls and the activity log are stored in the browser and can be edited by the person using it.Keep roles and an append-only audit log on a server, with signed entries.
